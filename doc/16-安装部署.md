# 16-安装部署

> 本文说明地检上位机的两类落地方式：**开发环境**（源码本机跑）与 **正式环境**（现场用 `dist/deploy` 安装脚本 + 更新包）。
>
> 设计文档索引见 [README](./README.md)。离线包与更新脚本细节以仓库 [`dist/README.md`](../dist/README.md)、[`dist/deploy/README.md`](../dist/deploy/README.md) 为准；本文做操作向汇总。

---

## 1. 两种环境对照

| | 开发环境 | 正式环境 |
| --- | --- | --- |
| 目的 | 改代码、联调、跑测试 | 现场机长期运行 |
| 代码形态 | Git 仓库源码 | `pgt-*.whl` + `html_*.zip` + `dist/pkg` |
| 安装方式 | 自建 venv / npm | 双击 `dist/deploy/install.bat`，再跑 `update.bat` |
| 安装目录 | 仓库任意路径 | 有 D 盘则 `D:\PGT`，否则 `C:\PGT` |
| 数据库 / Redis | 本机或 Docker，按 `.env.*` | 一般由安装脚本拉起的 Docker 容器（合成模式后端在 Windows） |
| 前端 | `npm run dev` 或本地 build | Nginx 静态目录 `PGT\nginx\html` |
| 采集 | 可嵌在后端，或单独 `app_collector` | 由模式决定：合成由后端拉起；分离由服务 `PGT` 跑采集 |

## 2. 开发环境

### 2.1 环境要求

| 组件 | 版本 | 依据 |
| ---- | ---- | ---- |
| Python | 3.11 – 3.13（推荐 3.13） | `ruoyi-fastapi-backend/pyproject.toml`、`Dockerfile.my` |
| Node.js | 18+（推荐 20） | Vite 6 |
| 数据库 | MySQL 8（默认）/ PostgreSQL / SQLite | `ruoyi-fastapi-backend/.env.*` 中 `DB_TYPE` |
| Redis | 6+（必需） | 采集与主进程通信 |

主要依赖以仓库文件为准：后端见 `ruoyi-fastapi-backend/requirements.txt`；前端见 `ruoyi-fastapi-frontend/package.json`。扩展包 **不在 PyPI**：`dist/pkg/` 下的 `gpcan`、`telemetryparser` wheel。

### 2.2 仓库目录（开发常用）

| 目录 | 说明 |
| ---- | ---- |
| `ruoyi-fastapi-backend` | FastAPI 后端；业务在 `module_payload` |
| `ruoyi-fastapi-frontend` | Vue3 + Element Plus |
| `ruoyi-fastapi-app` | 手机前端 |
| `ruoyi-fastapi-test` | Playwright E2E |
| `ruoyi-fastapi-hil` | 硬件在环相关 |
| `dist` | 正式环境安装/更新包、扩展 wheel、`deploy` 脚本 |
| `doc` | 设计与部署文档（本目录） |

### 2.3 准备数据库与 Redis

默认 `--env=dev` 使用 MySQL，连接在 `ruoyi-fastapi-backend/.env.dev`（`DB_*`、`REDIS_*`），按本机修改。

初始化库（SQL 在 `ruoyi-fastapi-backend/sql/`）：

```bash
# MySQL（默认）
mysql -uroot -p  --default-character-set=utf8mb4 -e "CREATE DATABASE IF NOT EXISTS \`ruoyi-fastapi\` DEFAULT CHARSET utf8mb4"
mysql -uroot -p  --default-character-set=utf8mb4 ruoyi-fastapi < ruoyi-fastapi-backend/sql/ruoyi-fastapi-my.sql

# PostgreSQL：导入 sql/ruoyi-fastapi-pg.sql，.env 中 DB_TYPE='postgresql'（另装 requirements-pg.txt）

# SQLite：使用 .env.sqlite，无需独立库服务
cd ruoyi-fastapi-backend
sqlite3 ruoyi-fastapi.db < sql/ruoyi-fastapi-sqlite.sql
```

Redis：本机 `redis-server`，或 `docker run -d -p 6379:6379 redis`。

### 2.4 后端

**Windows（cmd）**

```bat
cd ruoyi-fastapi-backend
python -m venv venv
venv\Scripts\activate.bat
pip install -r requirements.txt
pip install ..\dist\pkg\telemetryparser-1.0.1-py3-none-any.whl ..\dist\pkg\gpcan-1.2.1-py3-none-any.whl

python app.py --env=dev
```

**采集监工（与网页分开跑）**

```bat
cd ruoyi-fastapi-backend
venv\Scripts\activate.bat
python app_collector.py --env=dev
```

不传 `--env` 时采集侧常用 `.env.prod` 约定，以脚本/文档当前说明为准。`COLLECTOR_EMBEDDED=true` 时仍可由后端进程内嵌拉起监工（见 [01](./01-系统总体设计.md)、[02](./02-数据采集层设计.md)）。

### 2.5 前端

```bat
cd ruoyi-fastapi-frontend
npm install
npm run dev
```

开发服务器默认端口以 Vite 配置为准（常见 `http://localhost:80` 或 `5173`，看终端输出）。

### 2.6 访问与账号

- 前端开发地址：终端打印的 Local URL
- 后端 API：以 `.env.dev` / `app.py` 监听为准（常见 `9099`）
- 默认管理员账号以导入的 SQL 为准（若依体系，常见 `admin`；密码以库内初始化数据为准）

### 2.7 测试

| 测试 | 位置 | 命令 |
| ---- | ---- | ---- |
| 后端 pytest | `ruoyi-fastapi-backend/tests` | `cd ruoyi-fastapi-backend && python -m pytest tests` |
| 前端 Vitest | `ruoyi-fastapi-frontend/tests` | `cd ruoyi-fastapi-frontend && npm run test:run` |
| E2E Playwright | `ruoyi-fastapi-test` | Windows：`run_test.bat`；详见该目录 README |

CI：`.github/workflows` 下 `unit-tests.yml`、`playwright.yml`、`ruff.yml`。

### 2.8 开发机为正式包准备依赖缓存（可选）

正式环境离线安装需要 `dist/pkg/pkg_cache`。在**能联网**的机器上：

```bat
cd dist\pkg
get_pkg_cache.bat
```

再把整个 `dist` 拷到现场机。打更新包、补丁版本规则见 [`dist/README.md`](../dist/README.md)「说明（开发人员）」。

## 3. 正式环境部署

正式环境面向 Windows 现场机：**先** `install.bat` **装基础环境与模式，再** `update.bat` **装入当前版本的后端 whl / 前端 zip / 依赖与库补丁**。不要用开发环境的 `python app.py` / `npm run dev` 当现场常驻方式。

### 3.1 包从哪来

交给现场的内容（更新包，也常与首次安装一起拷贝）：

| 内容 | 作用 |
| ---- | ---- |
| `dist/deploy/install.bat` 及 `deploy/` 下 Docker/解压等 | **首次**装基础环境（仅首次或重装基础时需要） |
| `dist/update.bat` | **安装完成后的版本落盘与更新**（新装后也必须跑一次） |
| `html_*.zip` | 前端静态资源 |
| `pgt-*.whl` | 后端包 |
| `pkg/`（含 `gpcan`、`telemetryparser`；有条件带 `pkg_cache`） | 依赖 |
| `db/`、`db/patches/` | 初始库与补丁 |

开发打更新包时**不**把 `deploy`、history 放进「仅更新」压缩包；**首次安装**需带上完整 `dist`（含 `deploy`）。详见 [`dist/README.md`](../dist/README.md)。

### 3.2 安装模式（`install.bat`）

双击 `dist/deploy/install.bat`（自动提权），选择：

| 选项 | 含义 |
| ---- | ---- |
| **1 采集端** | 只装采集，不装 Docker；填采集机标识、服务端地址（默认标识 `local`、地址 `127.0.0.1`），连服务端 Redis |
| **2 服务端** | Docker 中跑 mysql、redis、nginx、后端容器 `backend` |
| **3 本机服务端+采集端** | 等同 1+2（分离模式两角色同机） |
| **4 合成模式** | 后端在 Windows 运行并自行拉起采集；mysql / redis / nginx 在 Docker |

也可命令行：`install.bat 1 <采集机标识> <服务端地址>`、`install.bat 2`、`install.bat 3`、`install.bat 4`；别名 `both`/`all`=3、`embedded`=4。

模式写入 `<安装目录>\releases\role.env`。无该文件时更新脚本按**合成模式**处理。合成与分离互相切换会要求确认。选 1、2 可在已装分离模式上追加角色。

涉及注册 Windows 服务 **PGT** 时（采集端 / both / 合成等），在 Redis 相关询问后会问是否**开机自启**；选 N 仍注册服务，但关闭自启。

### 3.3 首次安装步骤（现场）

1. 将完整 `dist` 拷到现场机（建议桌面或 U 盘路径，避免中文/权限怪异路径）。
2. 双击 `deploy\install.bat`，选模式；若提示 **Please restart the system**：重启 → 登录 → 打开 Docker Desktop 等到就绪 → **再跑一遍** `install.bat`。
3. 安装目录：有 D 盘为 `D:\PGT`，否则 `C:\PGT`。
4. 安装结束后，双击更新包根目录的 `update.bat`，把当前 `pgt-*.whl` / `html_*.zip` / 补丁装进 `D:\PGT`（没有 `releases\current.txt` 时，服务起来后会直接退出，因此新装后必须更新一次）。
5. 基础环境就绪后，`deploy` 目录可删（见 deploy 说明）；日常只保留更新包流程。

桌面会生成 PGT 相关快捷方式；可用 `<安装目录>\service\init\desktop_shortcut.bat` 重建。

### 3.4 日常更新（现场）

1. 把更新包（含 `update.bat`、`html_*.zip`、`pgt-*.whl`、`pkg`、`db\patches` 等）拷到现场。
2. 双击 `update.bat`，确认 UAC；**不必**先手动 `stop_py`。
3. 看到 `[OK]`：完成；看到 `[ERROR]`：旧版本应仍在跑，把 `D:\PGT\data\logs\install\` 最新日志与窗口截图发给开发。

`update.bat` 读 `role.env`：合成走 `update_embedded.bat`；分离先服务端再采集端。失败时合成/服务端/采集端脚本会按设计尝试回滚（健康检查：后端 `9099/health`，采集查 Redis 快照键）。细项见 [`dist/README.md`](../dist/README.md)。

单独更新示例（在已安装机上）：

```bat
D:\PGT\service\update\update_frontend.bat "<更新包目录>"
D:\PGT\service\update\update_embedded.bat "<更新包目录>"
D:\PGT\service\update\update_server.bat "<更新包目录>"
D:\PGT\service\update\update_collector.bat "<更新包目录>"
D:\PGT\service\update\db_patches_apply.bat "<更新包目录>"
```

可加第二参数 `nopause`。

### 3.5 运行、停止与网络要点

- **启停**：用桌面 `start_py` / `stop_py`，或 `net start PGT` / `net stop PGT`。不要强杀 `python.exe`（会被服务拉起）。
- 服务开机后先等约 **90 秒**；合成模式还要等 Docker；采集端要等服务端 Redis 可达。Docker Desktop 需用户登录后才起来。
- **服务端防火墙**：开放 80、12580；6379 对本地子网（Redis 无密码，仅可信局域网）。MySQL 绑 `127.0.0.1`。
- **nginx 上游**：服务端（选 2/3）反代 `http://backend:9099/`；合成（选 4）反代 `http://host.docker.internal:9099/`。`install.bat` 按模式选用 `docker_to_docker` / `docker_to_windows` 配置模板。
- **卸载基础服务**：`<安装目录>\service\init\uninstall.bat`（删服务与容器；镜像、数据、安装目录默认保留）。

### 3.6 正式环境日志

| 类别 | 路径 |
| ---- | ---- |
| 安装/更新 | `D:\PGT\data\logs\install\`（合成 `backend_*.log`，服务端 `server_*.log`，采集 `collector_*.log`） |
| 服务 PGT | `D:\PGT\data\logs\service\` |
| 后端容器 | `docker logs backend` |
| nginx / mysql8 / redis | `D:\PGT\nginx\logs\`；`docker logs mysql8`；`docker logs redis` |

### 3.7 数据库（正式）

- 现场只用 **MySQL**。
- 新装：数据目录为空时执行包内 `PGT/mysql/sql`（含当时基线补丁）。
- 更新：`db_patches_apply.bat` 只跑未成功补丁；已执行补丁校验 SHA-256，改过则失败停止。采集端不跑库补丁。
- 开发侧补丁命名与打进 `dist/db` 的规则见 [`dist/README.md`](../dist/README.md)「数据库」一节。
